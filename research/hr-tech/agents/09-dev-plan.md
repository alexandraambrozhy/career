## 1. Краткое резюме

1. **MVP — одна воронка «Карьерный профиль».** Бесплатный профиль на 9–12 минут (IPIP Big Five, 50 пунктов, + сокращённая ORVIS, 8 шкал интересов) → бесплатная карточка → платный отчёт «3–5 направлений для проверки + план проб на 30 дней» → платный разбор у заказчицы → опрос исходов через 30 и 90 дней. В MVP нет: чат-коуча, оценок по тексту, клинических шкал, найма, мобильного приложения и кабинета консультанта (кабинет — этап Н4, недели 25–32). [И]
2. **Стек — три варианта, рекомендуется последовательный путь В → А.** **(В)** «Без ПДн» (недели 2–8): статический сайт, подсчёт и бесплатная карточка в браузере, оплата по ссылке Robokassa/ЮKassa, анонимные ответы без идентификаторов на российский сервер. **(А)** «Веб + российский бэкенд» (с недели 9): тот же фронтенд + TypeScript API + PostgreSQL на VPS в РФ (Timeweb Cloud от ~188 ₽/мес [Ф, C]; Selectel или Yandex Cloud как альтернатива), Docker Compose, зашифрованные ночные бэкапы в российское S3. **(Б)** Telegram-бот — только как дополнительный вход и канал напоминаний, не основной: с февраля 2026 года РКН замедляет Telegram [Ф, B]. [И]
3. **Supabase, Vercel-БД, Airtable, Google Forms, Tally и зарубежные CDN не используются для ПДн** (05 КЛ-1). Cloudflare с июня 2025 года замедляется из РФ (пропускаются первые ~16 КБ) [Ф, B], поэтому статика тоже размещается в РФ: на том же VPS или в Yandex Object Storage. Причина — доступность, а не закон. [И]
4. **Психометрический движок — детерминированный и версионируемый.** Банк заданий хранится в git как YAML (ID пункта, ключ «+/−», шкала, источник IPIP, лицензия, статус). Подсчёт — одна чистая TypeScript-функция для браузера и сервера. Обратные пункты: `6 − x`. Пропуски: до 20 % на шкалу. Флаги качества: внимание, скорость, однообразные ответы. Нормы растут по стадиям: POMP 0–100 при N < 150 → процентили пилотной выборки с подписью «по пользователям сервиса, N = …, дата» → квотные нормы после выручки. Выгрузка для R/JASP: псевдонимный research ID, сырые ответы, codebook, только при согласии «исследование». [И]
5. **LLM — только «перо», не «судья».** Баллы, выбор направлений и флаги считает код по правилам. LLM (GigaChat или YandexGPT, данные в РФ) пересказывает готовые блоки текста и собирает план проб из библиотеки заказчицы. Выход проверяется валидатором (JSON-схема, стоп-слова, сверка чисел); при сбое подставляется шаблонный текст. Стоимость — **0,5–15 ₽ на платный отчёт** [Ф/Г: GigaChat Lite подешевел до 0,065 ₽ за 1 000 токенов, B; YandexGPT Lite около 0,20 ₽, A/C 2024]. В бесплатной части LLM не используется. [И]
6. **Разработку ведут 9 агентов Claude Code с передачей работы через файлы-контракты в репозитории:** Spec → (UX/контент ∥ Психометрист) → Backend → Frontend → AI → QA (непрерывно) → Security (гейты перед сбором ПДн и перед платным запуском) → Growth (параллельно с недели 1). Партнёр — QA (Excel-пересчёт 30–50 наборов), операционка и ревьюер PR. Заказчица — содержание, решения и приёмка. Живые специалисты нужны в трёх точках: эксперты перевода по ITC, юрист по ПДн, рецензент-психометрист. [И]
7. **Сроки: 36 недель (9 месяцев), сжатый вариант — 26 недель.** Дискавери и предзаказ — недели 1–4. Прототип — 5–8. MVP с ПДн — 9–14 (релиз 18.01.2027). Пилот и выборка N ≈ 300 — 15–24. Платный запуск — 20–28. Н4: консьерж-пилот 16–20, кабинет 25–32, подписка с недели 32. **Часы на проект:** заказчица — около 330 ч на продукт и науку (≈ 9 ч/нед.) из своих ~720 ч за 9 месяцев; остальное время уходит на контент и консультации. Партнёр — около 236 ч (≈ 6–7 ч/нед.). [Г]
8. **Бюджет до первой выручки — 3–10 тыс. ₽** (домен, VPS, бэкапы, посевы; LLM во freemium; документы по шаблонам). **Рекомендуемый — ≈ 45–50 тыс. ₽:** + проверка юристом 15–25 тыс. ₽, посевы 10 тыс. ₽, вознаграждения за ретест 5 тыс. ₽. **Комфортный — ≈ 220–320 тыс. ₽:** + рецензент-психометрист, дизайнер, маркетинг, частичная панель. Для каждой платной позиции указана бесплатная замена (§8). Грант Yandex Cloud Boost «Start» (около 50 тыс. ₽ на 6 месяцев для команд с демо, C, 06.2026) — бонус, не основа плана. [Ф/Г]
9. **До старта от заказчицы нужны 12 решений** (главные: оператор ПДн — заказчица как самозанятая; состав и длина теста; LLM-провайдер; цены пакетов; домен), 9 доступов и контент: тексты интерпретаций (13 шкал × 3 уровня), карта «интересы × черты → направления» на 40–60 направлений, библиотека проб, тексты согласий (§9).
10. **Главные риски:** выборка не наберётся (самое узкое место), ошибка ключей или подсчёта, утечка ПДн, галлюцинации LLM с медицинской лексикой, недоступность Telegram и Cloudflare, перегрузка заказчицы разборами, зависимость от одного провайдера. Меры и контрольные точки — в §10.

## 3. Варианты стека

### 3.1. Сравнение трёх вариантов

| Критерий | **(А) Веб + бэкенд и PostgreSQL в РФ** | **(Б) Telegram-бот + БД в РФ** | **(В) Без ПДн: всё в браузере** |
|---|---|---|---|
| Суть | статический фронт (Astro + React-острова или Vite + React, TypeScript) + API (Node.js, Hono или Fastify) + PostgreSQL 16 на VPS в РФ; Caddy (TLS), Docker Compose | бот на grammY (TypeScript) или aiogram (Python); вопросы — кнопками; оплата через Telegram Payments с ЮKassa или ссылкой; БД на VPS в РФ | статический сайт; подсчёт, карточка и бесплатный отчёт в браузере; платный отчёт — после оплаты по ссылке (код разблокировки или ручная отправка); анонимные ответы — POST на российский эндпоинт |
| Где хранятся ПДн | только в РФ (VPS, бэкапы в российском S3) | Telegram ID и переписка проходят через инфраструктуру Telegram (зарубежную); наша БД — в РФ. Квалификация переписки как трансграничной передачи не ясна [Г, к юристу] | у нас — нигде; e-mail и телефон для чека собирает платёжный сервис как самостоятельный оператор [И] |
| Стоимость в месяц [Ф/Г] | VPS 1 vCPU / 1–2 ГБ: от ~188 ₽ (Timeweb, рейтинг, C), реалистично 300–600 ₽ [Г]; S3-бэкапы < 50 ₽ [Г]; домен 200–900 ₽ в год [Г] | то же, что А, минус фронтенд | 0–200 ₽: хостинг статики в Yandex Object Storage (платно по объёму, копейки [Г]) или на том же VPS |
| Сложность для ИИ-агентов | средняя: стандартный CRUD, вебхуки, роли | средняя: состояние диалога, ограничения UI кнопок, длинные опросники неудобны | низкая |
| Время до запуска | 5–6 недель (недели 9–14) | 3–4 недели | 1–2 недели |
| Что даёт для науки | полноценно: ретест, исходы 30/90, согласия, выгрузка | полноценно, но выше отсев на длинном опроснике [Г] | только одномоментные анонимные данные; ретест — только через код, который человек сохранит сам |
| Риски | ответственность оператора ПДн: утечка — штрафы от 3 млн ₽ для юрлиц (05 §2.1) и защита на нас | **Telegram замедляется РКН с 02.2026**, слухи о полной блокировке (B, 2026) [Ф]; блокировки ботов самим Telegram; зависимость от платформы | платный отчёт можно переслать другим; нет повторных продаж и follow-up; аналитика воронки слабее |
| Пригодность для Н4 | высокая: кабинеты, роли, мультиарендность | низкая: брендирование и PDF неудобны | нет |
| Вердикт [И] | **основной контур с недели 9** | **дополнительный вход (неделя 20+):** «пройти в Telegram» и напоминания, данные в той же БД | **прототип и предзаказ (недели 2–8):** быстро, 0 ₽, ноль регуляторного риска |

**Почему не no-code (Tilda + Tally + Airtable + Make).** Tally и Airtable хранят данные за рубежом, а значит нарушают КЛ-1. Российские конструкторы (Tilda — компания с российскими корнями, серверы которой сейчас, по открытым данным, не в РФ [Г, не проверено]; формы «Яндекса»; Anketolog) не дают подсчёта с обратными пунктами, версионирования, ретеста и выгрузки. На российских конструкторах можно сделать только R0, а основной контур — нет. [И]

### 3.2. Подварианты для (А): где поднимать бэкенд

| Подвариант | Плюсы | Минусы | Стоимость [Ф/Г] |
|---|---|---|---|
| **А1. VPS (Timeweb Cloud, Selectel, Beget и др.) + Docker Compose (рекомендуется)** | обычный PostgreSQL; одна машина; ИИ-агенты хорошо знают такой стек; легко переехать | администрирование (обновления, бэкапы) на нас; партнёр должен уметь по инструкции перезапустить сервис | от ~188 ₽/мес (Timeweb, C) до ~600 ₽ за 2 ГБ RAM [Г] |

Yandex Cloud serverless:** Cloud Functions + API Gateway + YDB serverless + Object Storage | бесплатный уровень каждый месяц: 1 млн вызовов функций и 10 ГБ×ч, YDB — 1 млн RU и 1 ГБ (страница обновлена 30.06.2026) [Ф, A]; нет серверов | YDB — не PostgreSQL (другой SQL-диалект, сложнее для R-выгрузок); холодный старт; разработка сложнее; физлицам доступен только стартовый грант на 60 дней (сумма не подтверждена), пробного периода нет [Ф, A] | 0 ₽ в пределах free tier |

## 4. Психометрический движок

### 4.1. Состав опросника (решение D3 за заказчицей)

| Вариант | Состав | Время [Г] | Плюсы | Минусы |
|---|---|---|---|---|
| **Рекомендуемый** | IPIP Big Five 50 маркеров (5 × 10) + ORVIS, сокращённая до 6 пунктов на шкалу (8 × 6 = 48) | 9–12 мин | домены надёжны; 6 пунктов на шкалу хватает для ω и EFA | ORVIS-короткую нужно собрать самим по нагрузкам из оригинала → это новая форма, её психометрика не известна [Г] |
| Короткий | Mini-IPIP 20 + ORVIS 4 × 8 = 32 | 6–7 мин | выше доля завершивших, ближе к «15–25 вопросам» из 05a §2.2 | надёжность 4-пунктовых шкал низкая; слабее для препринта |
| Исследовательский | IPIP-50 + полная ORVIS (число пунктов сверить на ipip.ori.org; по памяти — около 90) | 15–18 мин | максимум данных, можно потом выбрать короткую форму по пилоту | отсев; не подходит как лид-магнит |

**Рекомендация [И]:** рекомендуемый вариант как основной, плюс «исследовательский хвост» — до 40 дополнительных пунктов ORVIS, которые получают 20 % случайно выбранных согласившихся на исследование (планированный пропуск, planned missingness). Так к N ≈ 300 будут данные по всем пунктам ORVIS, а короткую форму v2 можно пересобрать по реальным нагрузкам.

### 4.2. Банк заданий и версионирование

```
/item-bank
  instruments/ipip-bf50.yaml        # пункты, ключи, источник, лицензия
  instruments/orvis.yaml
  forms/kp-form-1.0.0.yaml          # упорядоченный список item_id + блоки + проверки внимания
  translations/ru/…                 # перевод, обратный перевод, протокол экспертов (ITC)
  norms/norms-2027-04-ru-pilot-n312.json
  CHANGELOG.md
```

Поля пункта: `item_id` (неизменяемый, например `BF_E_01`), `source_id` (код пункта в IPIP), `scale`, `key` (+1 / −1), `text_ru`, `text_en`, `response_format` (likert5), `status` (`draft` / `pilot` / `active` / `retired`), `translation_version`, `license` (`public-domain IPIP`, ссылка), `notes` (решения экспертов).

**Правила версионирования [И]:**
- форма имеет семантическую версию: **major** — меняется состав или ключ, баллы несравнимы; **minor** — правка формулировки, сравнимость надо проверять; **patch** — опечатка;
- опубликованная форма неизменяема; каждый ответ хранит `form_version`, каждый балл — `scoring_version` и `norm_version`;
- пункты со статусом `pilot` показываются, но в балл не входят (A/B формулировок);
- любое изменение ключа или формы проходит через PR с ревью Психометрист-агента и партнёра (пересчёт Excel).

### 4.3. Подсчёт баллов

| Шаг | Правило [И, по 04 §2.9 и практике IPIP] |
|---|---|
| Обратные пункты | `x' = 6 − x` для `key = −1` (шкала 1–5) |
| Пропуски | балл шкалы считается, если отвечено ≥ 80 % пунктов шкалы (8 из 10, 5 из 6); среднее по отвеченным; иначе `NA` и сообщение в отчёте |
| Сырой балл | среднее (1–5) |
| POMP | `(mean − 1) / 4 × 100` — до появления норм |
| Процентиль | по таблице норм нужной версии (§4.4) |
| SEM и интервал | `SEM = SD × √(1 − ω)` из пилота; в отчёте 90 % интервал; до пилота — консервативное ω = 0,75 из литературы [Г] |
| Флаги качества | 2 пункта-инструкции («выберите "Скорее согласен"»), медианное время ответа < 1,5 с, ≥ 12 одинаковых ответов подряд, `psych::` long-string. При ≥ 2 флагах — мягкое предупреждение пользователю и исключение из исследовательской выборки |
| Интересы | ипсативный «топ-3» не считаем: показываем все 8 шкал + 3 самые высокие с пометкой «разница меньше интервала — шкалы равны» |

**Контроль корректности (критично):**
1. Золотой набор: 50 векторов ответов, включая крайние (все 1, все 5, чередование, пропуски) — подсчёт в Excel у партнёра, независимо от кода.
2. Юнит-тесты сравнивают код с золотым набором до 4-го знака.
3. Property-тесты: инверсия всех ответов меняет знак отклонения; перестановка пунктов не меняет балл.
4. Ключи сверяются с ipip.ori.org двумя людьми: Психометрист-агент + заказчица, протокол сверки в репозитории.

### 4.4. Нормы по стадиям

| Стадия | Когда | Что показываем | Подпись в отчёте |
|---|---|---|---|
| 0 | N < 150 | POMP и словесные зоны относительно середины шкалы, без сравнения с людьми | «Сравнение с другими пользователями появится, когда наберётся достаточно данных» |
| 1 | N ≥ 150 после очистки | процентили по пилоту, сглаженные (без деления на пол и возраст) | «Бета-нормы: пользователи сервиса, N = 168, март 2027. Не представительная выборка россиян» (04 §3.2 п. 6) |
| 2 | N ≥ 300, затем раз в квартал | пересчёт; проверка различий по полу и возрасту; при заметных различиях — регрессионные нормы (`gamlss`) после консультации рецензента | версия норм и дата в каждом отчёте; старые отчёты не пересчитываются молча |
| 3 | после выручки | квотная панель от 1 000 человек (04 §2.10, 100–300 тыс. ₽ [Г]) | «Нормы по квотной выборке взрослых РФ, N = …» |

Таблица норм — JSON-файл в git: перцентильные точки для каждой шкалы, N, дата, критерии исключения, хэш выгрузки, на которой построена.

### 4.5. Генерация отчёта

1. **Детерминированный слой (обязателен):** для каждой шкалы три зоны (низкая / средняя / высокая по интервалу) → тексты заказчицы (13 шкал × 3 зоны × 2 версии длины). Блок «Ограничения интерпретации» в каждом отчёте (05 §4 п. 5).
2. **Правила направлений:** таблица заказчицы «шкала интересов ORVIS + условие на черты → направление для проверки + аргументы за и против». Движок выбирает 3–5 направлений с наибольшим совпадением и показывает, *что в профиле поддерживает* и *что против* — без слов «вам подходит».
3. **LLM-слой (только в платном отчёте):** связный пересказ и план проб на 30 дней (§5).
4. **Проверка эффекта Барнума (04 §2.2):** в пилоте 10 % согласившихся получают в конце опрос «насколько отчёт про вас» по двум отчётам — своему и чужому, перемешанному (A/B на исследовательской подвыборке, с раскрытием после ответа). Цель — разница в оценках точности ≥ 0,5 балла [Г].
5. **Форматы:** веб-страница, PDF, карточка 9:16 (PNG, рендер на клиенте).

## 5. LLM: где можно, где нельзя, сколько стоит

### 5.1. Карта применения

| Где | Можно? | Как |
|---|---|---|
| Пересказ интерпретации в платном отчёте | **да** | вход: JSON с зонами шкал, выбранными направлениями и утверждёнными блоками текста; задача — связать, а не придумать |
| План проб на 30 дней | **да** | выбор из библиотеки проб заказчицы (информационное интервью, мини-проект, курс-проба, волонтёрство) + адаптация под направление |
| Черновик заметок к разбору для заказчицы | **да** (внутренний) | вопросы для сессии по профилю; видит только заказчица |
| Черновик перевода пунктов и текстов, контент | **да, только черновик** | без ПДн; люди проверяют по ITC |
| Подсчёт баллов, выбор направлений, флаги | **нет** | только код (05 КЛ-9) |
| Оценка личности по свободному тексту, голосу, видео | **нет** | 04 §3.2 п. 5, 05 КЛ-7 |
| Свободный чат с пользователем, «AI-коуч» | **нет в MVP** | нужен кризисный протокол, логи, оценка качества (06: Н9 отвергнута) |
| Ответы на вопросы о здоровье и состоянии | **нет** | кризисная маршрутизация §2.2 S8 |
| Отправка ПДн в зарубежный LLM | **нет** | 05 КЛ-8; используем GigaChat или YandexGPT, но и туда ПДн не отправляем |

### 5.2. Ограничители (guardrails)

1. **Минимизация входа:** в промпт попадают только зоны шкал, коды направлений и блоки текста. Имён, e-mail, свободного текста пользователя там нет; исключение — необязательное поле «текущая профессия» из списка-справочника, не свободный текст.
2. **Структурированный выход:** JSON по схеме (разделы, длина ≤ N символов); при невалидном JSON — один повтор, затем шаблонный текст.
3. **Валидатор (код):**
   - словарь запрещённых слов и корней: «диагноз», «расстройств», «депресс», «тревожн», «терап», «лечен», «коррекц», «нейро», «гарантир», «точно подходит», «ваша профессия», «тип личности»;
   - в тексте нет чисел, кроме переданных; нет направлений, которых нет во входе;
   - нет обращения по имени, нет ссылок.
4. **Фолбэк:** при любом срабатывании валидатора — шаблонный текст; отчёт не задерживается.
5. **Человек в контуре:** первые 50 платных отчётов заказчица вычитывает до отправки (около 5 мин на отчёт). Затем выборочно 10 %. Жалоба пользователя → разбор за 48 ч.
6. **Логирование:** провайдер, модель, версия промпта, температура (≤ 0,4), хэш входа, выход, результат валидатора, стоимость. Логи хранятся 12 месяцев, без ПДн.
7. **Оценка качества:** набор из 40 эталонных профилей (`evals/`): AI-агент прогоняет его при каждой смене модели или промпта. Метрики: доля прохождения валидатора ≥ 98 %, оценка заказчицы по рубрике (точность, тон, конкретность проб) ≥ 4 из 5.
8. **Абстракция провайдера:** интерфейс `generate(promptId, input) → output`; GigaChat и YandexGPT взаимозаменяемы, для будущего EU-контура — зарубежная модель на зарубежном сервере.

## 6. Состав агентов для разработки в Claude Code

### 6.1. Принципы организации

- **Монорепозиторий** с директориями-контрактами: `docs/prd/`, `docs/adr/`, `content/`, `item-bank/`, `packages/psychometrics/`, `apps/web/`, `apps/api/`, `llm/`, `evals/`, `legal/`, `growth/`, `qa/`.
- **CLAUDE.md** в корне: правила (никаких ПДн в репозитории, только синтетика; русский интерфейс; запрещённая лексика; тесты обязательны; номер версии формы в каждом расчёте).
- **Передача работы — через файлы, а не через «память»:** каждый агент заканчивает задачу файлом `handoff/NN-<agent>-<дата>.md` (что сделано, где, что не сделано, вопросы к людям). Следующий агент начинает с чтения последних handoff и PRD.
- **Одна задача = одна ветка = один PR.** Ревьюер-человек: партнёр (функциональность, расчёты), заказчица (тексты, психометрическое содержание).
- **Порядок запуска:** агенты запускаются как отдельные сессии Claude Code (или субагенты) по очереди. Параллельно работают только агенты с непересекающимися директориями.
